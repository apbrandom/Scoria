# Плейбук делегирования Qwen — как ставить задачи и учиться на результате

Не журнал прогонов (это `qwen_eval.md`) — здесь только ТЕКУЩИЙ лучший способ
формулировать задание для `claude-local` (Qwen3-Coder через Ollama, см.
`devlog.md` §45) и рубрика оценки результата. Оба файла обновляются каждый
раунд: `qwen_eval.md` записывает, что было и что решили; этот файл фиксирует
ПРАВИЛО, которое из этого следует. Раздел 3 — версии шаблона, чтобы видеть
прогресс диффом git, а не перечитывать весь журнал.

Цель связки: не только получить полезный результат от Qwen, но и чтобы
формулировки задач становились лучше от раунда к раунду — обучаются обе
стороны (Qwen — на конкретной задаче, Claude — на том, какая постановка
задачи сработала).

## 1. Шаблон промпта (v2)

Каждое задание Qwen собирается из этих обязательных частей — не пропускать
ни одну, каждая появилась как ответ на конкретную реальную ошибку (см. §2):

1. **Режим и скоуп.** Явно указать: READ-ONLY-анализ или РЕАЛЬНАЯ правка
   кода. Если правка — назвать РОВНО один файл (или одну функцию внутри
   файла). Никогда не давать "весь scripts/" или "весь каталог" одним
   заданием — доказанно даёт галлюцинации (задание №1, `qwen_eval.md`).
2. **Точная спецификация правки**, если это код: что именно изменить, каким
   должно быть поведение до/после, какие файлы НЕ трогать. Для report-задач —
   что именно искать (мёртвый код / нарушения конвенций / и т.д.).
3. **Требование кросс-референса** перед любым утверждением "не используется"
   / "мёртвый код" — явным grep/поиском по всему проекту, не по одному файлу.
   Без этого пункта — ложные срабатывания (задания №1-2).
4. **Явное требование реально вызвать Write/Edit**, а не просто написать
   текст в чат — и явно разрешить сказать "не смогла", если не получилось,
   вместо того чтобы придумать, что сохранила (задание №1: Qwen
   галлюцинировала "сохранила файл", которого не было).
5. **Что НЕ трогать** — явный список: физика корабля, архитектура/сеть,
   любые числа геймплейного баланса без явного разрешения. Соответствует
   правилу CLAUDE.md "не хардкодить" и общему принципу "не архитектурные
   правки без заказчика".
6. **Явное требование не запускать сама тесты как финальное доказательство** —
   Qwen может прогнать `tools/` сама для самопроверки, но ФИНАЛЬНУЮ приёмку
   всегда делает Claude независимым прогоном (никогда не доверять словам
   Qwen "тесты прошли" без личной проверки — общий принцип с самого начала
   эксперимента).

## 2. Рубрика оценки (заполнять в `qwen_eval.md` после каждого раунда)

| Критерий | Как проверить |
|---|---|
| Выполнила ли заявленное (Write реально произошёл?) | `git diff`/`git status` — файл действительно изменён? |
| Уложилась ли в скоуп (тот файл/функция, не больше)? | `git diff --stat` — список изменённых файлов |
| Ложные заявления (посчитать штуки) | перепроверить каждое утверждение "не используется"/"баг" через grep вручную |
| Тесты `tools/` после правки | Claude запускает САМ, независимо от слов Qwen |
| Качество кода (стиль, комментарии по-русски, конвенции CLAUDE.md) | ручной код-ревью диффа |
| Что изменить в шаблоне к следующему разу | одна строка вывода, переносится в §3 ниже |

## 3. История версий шаблона

- **v1 (2026-07-24/25, devlog §45)**: узкий скоуп + кросс-референс +
  принудительный Write. Только report-режим (правки кода не давали —
  `--permission-mode` не был выставлен, Write физически не проходил в фоне).
- **v2 (2026-07-27)**: добавлен пункт 6 (Claude сама перепроверяет тесты,
  не доверяя словам Qwen) и снят технический блокер — `claude-local()`
  теперь запускается с `--permission-mode acceptEdits` (см. `~/.zshrc`),
  поэтому с этого раунда Qwen впервые пробует реальную правку кода, а не
  только отчёт. Первая задача v2 — `scenes/fx/explosion.gd`, push_warning
  при неотвечающем duck-typed узле группы `"terrain"` (уже отмечено как
  безопасное в `audit.md` §3.4, просто не приоритетно само по себе).
  **Подтверждено раундом №4** (`qwen_eval.md`): Write прошёл сам, дифф чистый
  и в скоуп, попытка Bash (самостоятельный прогон тестов) корректно
  заблокирована permission-режимом, а честность Qwen ("не могу запустить,
  ограничения безопасности") держится даже без явного требования в этом
  месте промпта. Решение НЕ давать Bash-права Qwen даже для самопроверки —
  осознанное: независимая проверка Claude всё равно обязательна (пункт 6),
  так что выигрыша в доверии Bash-доступ не даёт, а риск неограниченного
  shell добавляет. Заодно опробована живая трансляция хода работы
  (`--output-format stream-json --verbose` + `jq`-фильтр в читаемый лог +
  `tail -f` в отдельном окне Терминала) — полезно для следующих раундов,
  когда важно видеть пошагово, что делает модель, а не только финал.
