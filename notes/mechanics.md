# Wings v1.30 — анализ оригинала (папка `reference/`)

Дата анализа: 2026-07-20. Источники: осмотр бинарников (hex), WINGS.DOC, COLORS.TXT,
строки из WINGS.EXE, программный разбор форматов, поиск в интернете.
Папка reference не изменялась — только чтение.

---

## 1. Технология / движок

- **DOS-игра 1996 года, автор Miika Virpioja (Финляндия).** Жанр — cave flyer
  («пещерный леталет»), наследник игры AUTS (умеет импортировать её уровни через LEVCONV).
- **Самописный движок, без готового игрового движка.** Собран **DJGPP** (порт GCC под DOS),
  32-битный защищённый режим:
  - `WINGS.EXE` — MZ-заголовок со стабом go32 (`stub.h generated from stub.asm by djasm`,
    строки `go32stub, v 2.00T`, `DJGPP` внутри бинарника);
  - `CWSDPMI.EXE` — стандартный DPMI-хост DJGPP, лежит рядом.
- Видео: **VGA 256 цветов** (меню-картинки 320×200, палитра 6-бит на канал 0–63).
- Звук: Sound Blaster (настройка через переменную `BLASTER`), музыка — трекерные
  модули **S3M/MOD** (в EXE есть проверки магии `SCRM` и `M.K.`).
- Мультиплеер: 1–8 игроков за одной клавиатурой (до 4 экранных раскладок) + modem/serial.
- Версия «Registered» (релиз группы Evidence, `EVDW130`), лимит по умолчанию 50 fps.

## 3. Форматы ассетов

### 3.1 `.PIC` — два разных формата под одним расширением
- **Тип A (экраны):** обычный **PCX** (заголовок `0A 05 01 08`), 320×200, 8 бпп,
  палитра VGA в конце файла (маркер `0x0C` + 768 байт). Открывается GIMP/ImageMagick
  после переименования в `.pcx`.
- **Тип B (спрайт-листы, `W.PIC`, `VGAFONT1.PIC`):** без заголовка, подряд кадры:
  `uint16 w, uint16 h, затем w*h байт несжатых 8-битных пикселей`. Палитры нет —
  используется палитра уровня/экрана. `W.PIC` = 72 кадра 15×15 (вращение с шагом 5°),
  `VGAFONT1.PIC` = 256 глифов 8×8.

### 3.2 `.SHP` — корабли
Всё little-endian:
```
char[4]  magic = "WSHP"
uint32   version = 1
uint32   nameLen
char[n]  name
int32    stat1      // 75–170   — прочность/броня (?)
float32  statF1     // 0.8–1.7  — масса/размерный множитель (?)
int32    stat2      // 38–58    — скорость поворота (?)
float32  statF2     // 0.04–0.08 — ускорение/тяга (?)
int32    stat3      // 1700–2400 — энергия/перезарядка (?)
int32    stat4      // 80–160
int32    stat5      // 1–2      — число пушек
затем 72 кадра:
  uint16 w (=15), uint16 h (=15), uint32 packedLen, byte[packedLen]
```
Кадры сжаты **PCX-подобным RLE**: байт ≥ `0xC0` → повторить следующий байт
(count = байт & 0x3F), иначе — литерал. Цвет `0xFF` — прозрачность
(типичная строка `CF FF` = 15 прозрачных пикселей). 72 кадра = поворот 360°/5°.

Извлечённые характеристики кораблей:

| Файл | Имя | s1 | F1 | s2 | F2 | s3 | s4 | пушек |
|---|---|---|---|---|---|---|---|---|
| NORMAL | default | 100 | 1.0 | 50 | 0.06 | 2000 | 100 | 1 |
| ARROW | arrow | 110 | 1.2 | 38 | 0.07 | 2400 | 100 | 1 |
| BAT | Bat | 130 | 1.1 | 50 | 0.07 | 1900 | 140 | 2 |
| CRUISER | cruiser | 120 | 1.1 | 48 | 0.05 | 2000 | 115 | 1 |
| DART | dart | 75 | 0.8 | 58 | 0.08 | 2200 | 80 | 1 |
| GDESTR | gargoyle | 165 | 1.65 | 46 | 0.06 | 1700 | 130 | 2 |
| TBOMB | TIE-bomber | 110 | 1.1 | 55 | 0.065 | 2000 | 120 | 1 |
| WDESTR | wdestr | 170 | 1.7 | 42 | 0.04 | 1900 | 160 | 2 |

(семантика полей — гипотезы по разбросу значений; уточнить экспериментально в DOSBox)

### 3.3 `.LEV` — уровни
```
byte[768]  палитра VGA (256 × RGB, значения 0–63; масштабировать ×4 для 8-бит)
uint16 w, uint16 h          — размер уровня в пикселях
byte[...]  RLE              — битмап уровня w*h пикселей (RLE как в §3.2, похоже построчный)
[опционально] uint16 bgW, uint16 bgH + RLE — параллакс-фон
             bgW = w/2 + 78,  bgH = h/2 + 45  (формула из WINGS.DOC; проверено:
             заголовок с такими размерами найден во всех уровнях, кроме GROUND и WAR —
             у них фона нет)
byte[~14]  футер настроек   — ~6 uint16: вероятности дождя/снега/бомбёжки,
             скорость воды и т.п. (вопросы MAKELEV); точная раскладка не установлена
```
Минимальный размер уровня 157×90. Уровень — это **один индексированный битмап**,
геймплейный смысл пикселя определяется диапазоном палитрового индекса (§3.4).

### 3.4 Семантика палитры (из COLORS.TXT) — ядро механики разрушаемой земли
| Индексы | Значение |
|---|---|
| 0 | Пустота (фон, летабельно) |
| 16 | Генератор воды |
| 32–37 | База (общая, серая) |
| 38–39 | Неразрушаемая база |
| 40–47 | Базы команд 1–4 (по 2 индекса) |
| 48 | Вода |
| 49–51 | Вода с течением (вниз/влево/вправо) |
| 52 | Пузыри |
| 53 | Снег |
| 54 | Огонь (фоновый, наносит урон) |
| 55–56 | Взрывчатая порода |
| 57–63 | Зарезервировано |
| 64–79 | Фон (нетвёрдое) |
| 80–95 | **Неразрушаемая** порода |
| 96–111 | Мягкая порода |
| 112–127 | Горящая порода |
| 128–255 | Обычная (разрушаемая) порода |
Первые 48 цветов фиксированы (палитра из COLORS.PCX), 48–255 — свободные.

### 3.5 `WINGS.SND` — банк звуков
Ровно 512 КБ, без контейнера (нет RIFF/VOC/Creative-заголовков). Содержимое —
сырой **8-битный PCM** (видны осциллограммы около нуля). В начале — небольшая
таблица (`2A 00 63 05 …`), вероятно смещения/длины сэмплов; точная раскладка
не декодирована. Для клона проще пересоздать/переозвучить эффекты.

### 3.6 Музыка
Полностью **стандартные S3M и MOD** — играются OpenMPT/libopenmpt, конвертируются
в OGG чем угодно. Никакой распаковки не требуется.

### 3.7 Конфиги
Все `.DAT`-конфиги — плоские бинарные дампы структур (int32/байтовые флаги),
`MENU_M.CFG` — обычный текст. Для клона не нужны.

## 4. Механика игры (из WINGS.DOC и строк внутри EXE)

- **Суть:** 2D-полёт ракеты в гравитации в разрушаемых пещерах, 1–8 игроков.
- **Победа в матче:** последний выживший должен **вернуться на базу**. Deathmatch-режим:
  респавн, +1 за килл, −1 за самоубийство, смена уровня после N киллов.
- **Базы:** ремонт корабля + смена оружия (кнопками поворота, стоя на базе);
  есть общие, командные и неразрушаемые базы.
- **Одиночный режим:** спасти 10 своих десантников с вражеской территории и вернуться на базу.
- **Оружие (31 вид, список из EXE):** Dumbfire, Troopers, Ion cannon, Multicannon,
  Shotgun, Splinterbomb, Bomb, Mine, Missile, Freezer, Poison, Harpoon, Nucleus,
  Grenade launcher, Bats, Teleport, Gravitor, Plastic explosive, Dirtball,
  Watercannon, Digger, Fireworks, Hellfire, Torpedo, Bouncer, Base, Cannon, Shield,
  Electric blast, Poison gas, Nuke.
- **Управление на игрока:** тяга, поворот влево/вправо, основное орудие, второе оружие.
- **Настраиваемая физика (меню Options):** Gravity, Air resistance, Ship strength,
  Load times (перезарядка), Kills/level, Starting weapon (default/last/random).
- **Окружение:** параллакс-фон, звёзды, текущая/волнующаяся вода с настраиваемой
  скоростью, снег, дождь, бомбёжки, мирные жители (unarmed/aggressive), огонь,
  взрывающаяся порода.
- **Прочее:** пауза/выход ESC, скриншот F12 → `screen.pcx`, лимит FPS (по умолч. 50),
  режимы AI (Human/Computer), команды (Team 1–4).

## 5. Инструменты для распаковки

**Готовых открытых распаковщиков форматов Wings/AUTS не найдено** (искал GitHub и
общий веб — только Unity-клон `jsuvanto/mighty-wings` без парсеров оригинала).
Но это не проблема:

- `.PIC` (тип A) и `COLORS.PCX` — обычный PCX: **GIMP, ImageMagick, XnView**.
- Музыка — стандартные S3M/MOD: **OpenMPT / libopenmpt**.
- `.LEV` и `.SHP` — форматы **полностью разобраны в этом документе** (палитра + RLE);
  рабочая логика декодера уже проверена при анализе, экспорт в PNG — скрипт на ~50 строк
  (написать на следующем шаге).
- `MAKELEV.EXE` в комплекте — можно собирать тестовые уровни в **DOSBox**;
  сама игра запускается в DOSBox / в браузере (dos.zone) как эталон поведения.
- На Internet Archive есть **Wings 1.40** и **Wings 2 v1.4.0 (2021, Windows-ремейк
  того же автора)** — полезные эталоны и источник недостающих файлов.

## 6. Выводы для Godot-клона

1. Уровень = индексированный битмап + палитра; класс материала = диапазон индекса.
   В Godot естественно хранить как `Image` + карта материалов; разрушение земли —
   правка битмапа (по образцу destructible-terrain).
2. Спрайты кораблей 15×15 × 72 поворота → в Godot достаточно одного спрайта
   с `rotation` (или перерисовать в большем разрешении).
3. Все оригинальные ассеты извлекаемы своими скриптами (PCX RLE + палитра).
4. Физика: гравитация + сопротивление воздуха + тяга/поворот, всё параметризовано.
5. Звук проще пересоздать; музыку можно конвертировать из S3M/MOD.
