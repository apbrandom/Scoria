# Оценка локальной модели (Qwen3-Coder-30B-A3B, через Ollama/claude-local)

Living-документ (в отличие от разового `audit.md`) — журнал того, как локальная
модель справляется с делегированными задачами, чтобы со временем понять,
какому классу работы её можно доверять без присмотра, а какому нет. Не
инструкция по работе с проектом (это `CLAUDE.md`/`architecture.md`), а трек-рекорд
конкретной модели.

## Зачем и как работает связка

- `claude-local` (обёртка в `~/.zshrc`) — отдельная сессия Claude Code,
  указывающая на локальный Ollama (`qwen3-coder:30b`, квант `q8_0`) вместо
  облачного API. Обычный `claude` не трогается, работает как раньше на подписке.
- Она читает тот же `CLAUDE.md` при запуске в этой же папке — общие конвенции
  проекта ей известны сразу, повторять их в промпте не нужно.
- **Разделение труда**: Qwen получает узкие, механически проверяемые задачи
  (документация, поиск легаси/дублей/несоответствий конвенциям) и пишет
  РЕЗУЛЬТАТ В ОТЧЁТ, не правит боевой код напрямую. Причина — модель слабее и
  без Sonnet/Opus-уровня присмотра; отчёт можно проверить перед тем, как
  что-то менять, правка "втихую" — нет. Это ограничение снимается только по
  мере накопления трек-рекорда ниже.
- **Асимметрия ресурса**: у Qwen нет ни токенового бюджета, ни лимита по
  времени (локальная модель, не облачная подписка) — в отличие от Sonnet/Opus,
  где именно экономия токенов и есть главная причина всей этой связки. Значит
  задачи для неё нужно ставить БЕЗ привычной экономии на глубину анализа —
  явно разрешать ей идти по всему дереву файлов исчерпывающе, не сокращать
  выборку "для скорости", при необходимости работать часами/сутками без
  присмотра. Не нужно писать компактные промпты как для облака — наоборот,
  чем подробнее и полнее задание, тем лучше используется её главное
  преимущество (время, не деньги).

### 2026-07-24/25 — инфраструктура: две ночи багов ДО первой реальной задачи

Задача (что попросили): первое реальное задание (документация + поиск
легаси, `notes/qwen_prompt_2026-07-24.txt`) — но прежде чем оно смогло
выполниться, три независимые проблемы в самой связке `claude-local`↔Ollama.

Результат/находки (по порядку, каждая подтверждена логами, не гаданием):
1. На машине не было ни `node`/`npm`, ни самого CLI `claude` — обёртка из
   `~/.zshrc` была нерабочей с самого начала (`claude-local: command not
   found`). Поставили node через Homebrew, сначала случайно x64/Rosetta
   (`brew` резолвился в `/usr/local`, не `/opt/homebrew`) — CLI ругался
   "native binary not installed... AVX not emulated". Пересобрали на родной
   arm64 `/opt/homebrew`, подчистили дубль в `/usr/local/bin/claude`.
2. Тег модели в обёртке был `qwen3-coder:30b` — реальный тег в `ollama list`
   `qwen3-coder:30b-a3b-q8_0`. "Model does not exist" до тех пор, пока не
   поправили.
3. `OLLAMA_CONTEXT_LENGTH=65536` в обёртке — переменная окружения КЛИЕНТА,
   а демон `ollama serve` (запущен через GUI-приложение с четверга) её не
   видит и не может увидеть задним числом. Взяла максимум модели — 262144
   токена контекста → KV-кэш раздул `llama-server` до ~53 ГБ RSS (83% из 64
   ГБ) → своп на 6 ГБ. Фикс — не переменная, а `Modelfile` с `PARAMETER
   num_ctx`, привязанный к самой модели (`ollama create qwen3-coder-local`),
   не зависит от того, как стартовал демон.
4. Даже после фикса (3) — первое реальное (большое) задание падало с HTTP
   500 в логе `~/.ollama/logs/server.log` ("model does not support thinking,
   relaxing thinking to nil") ПОСЛЕ 4м38с честной обработки промпта (93%
   готово). Гипотеза "выключить thinking через `--effort low`" оказалась
   ЛОЖНОЙ (проверено отдельным маленьким тестовым промптом — ошибка
   осталась). Настоящая причина: системный промпт+схемы инструментов самого
   Claude Code съедают ~55-65К токенов ДО единого слова задачи — при
   контексте 65536 запрос буквально упирался в потолок (task.n_tokens было
   62937-65438, `n_ctx_slot`=65536), генерации отвечать было физически
   некуда. Подняли контекст до 131072 (Modelfile), выигрывая себе запас под
   реальную задачу и вывод.

Оценка: это НЕ про качество ответов Qwen — ни одна из четырёх проблем не
про то, ошиблась ли модель в коде. Все четыре — инфраструктурные баги
связки claude-local↔Ollama, которые проявляются ДО того, как модель
вообще увидела задачу. Важный урок: у Claude Code как агентского харнесса
(даже без единого вызова инструмента) фиксированный оверхед системного
промпта ~55-65К токенов — это нужно закладывать в бюджет контекста для
ЛЮБОЙ будущей задачи через эту связку, не только для этой.

Вывод: доверять пока рано — ещё не видели ни одного реального ответа Qwen
на содержательную задачу. Следующая итерация цикла (после этого фикса)
должна дать первый настоящий результат — тогда появится содержательная
оценка качества, а не только инфраструктуры.
